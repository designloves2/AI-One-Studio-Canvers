## 발견사항 (ID | 항목 | 심각도 | 재현)

### T-01 — 캐스팅 재작성 JSON 트렁케이션 & 음악 필드 환각 (R2/R6, 심각도 높음, 재현율: 항상에 가까움)
**재현 절차**
1. 실 LLM(comfy)로 "[TEST] 광고 20초, 아웃도어 재킷, 클립 10초" 진행해 캐스팅 단계까지.
2. 채팅에 "주인공 모델은 20대 한국 여성으로 해줘. 남성 모델은 빼고…" 류의 자유 지시 입력.
3. 4B·gemma4_e4b 모두 캐스팅 재작성 JSON을 **같은 위치 근처(≈5.7–5.9k 자)에서 트렁케이션**하며 `Expected ',' or ']' after array element in JSON at position 5711/5923` 실패. gemma4_e4b는 330초+ 동안 응답 없음(HTTP 500 후 인터럽트).
4. 일부 실패 응답에는 **광고 프로젝트에 없어야 할 `music` 필드/`뮤직 감독` 메시지**가 실려, 결국 `canvases\[TEST] 광고 20초, 아웃도어 재킷, - song.json`(3카드) 캔버스까지 생성됨(사이드 이펙트).

**기대**: 캐스팅 수정 지시가 JSON으로 정상 적용되고, 비뮤직 프로젝트에 음악 데이터가 생기지 않는다.
**실제**: 반복 실패 + 뮤직 환각 캔버스 파일 생성. Qwen3 9B로 교체 후에는 성공하고 "여성 한 명" 반영.
**증거**: 채팅 오류 원문 `...at position 5711 (line 116 column 3)`, `...at position 5923 (line 1 column 5924)`; 네트워크 500 (`/tj_studio_one/llm/enhance`); `- song.json` 파일 존재(1478B, 3카드).
**의심 위치**: 로컬 텍스트 인코더의 출력 토큰 예산이지 앱 로직이라기보다 LLM 선택/설정 문제(ComfyUI TextGenerate 경유). 추측 표기.
**제안**: (코드 수정 금지 지침상) 보고서로만 — 큰 모델(9B+) 또는 출력 예산·max_tokens 재검토, 비뮤직 프로젝트에서 `music` 응답 필드는 적용 시 폐기하도록 앱 검증 강화.

### T-02 — 광고(비뮤직)의 "완성 영상(클립 합치기)" 버튼이 항상 막힘 (G10, 심각도 높음, 재현율: 항상)
**재현 절차**
1. 광고 프로젝트를 검토 단계까지 완료(2클립 생성됨).
2. "클립 합치기" 클릭.
**기대**: 스티치가 실행되거나, 버튼이 비뮤직 형식에서 숨겨지거나 비활성화되어야 함.
**실제**: `캔버스에 완성본 카드(영상 스티치)가 없습니다. "Canvers 캔버스 업데이트"를 누르세요.` 대화상자만 반복. adapter의 `finish`(stitch/audio)가 `format==='musicvideo'`일 때만 카드를 만드므로 광고·드라마용 캔버스에는 스티치 카드가 아예 없음(때문에 위 안내가 항상 뜸).
**증거**: 대화상자 원문; `canvasAction.ts` L73-74 `finish = p.series.format === 'musicvideo' ? {...} : undefined`; `musicAction.ts` L119 `if (!link?.final_node_id) throw ...`.
**의심 위치**: `src/director/canvasAction.ts`(finish 조건), `src/director/DirectorView.tsx` FinalBlock 표시 조건.
**제안**: 비뮤직 형식에서 완성본 버튼을 숨기거나, 모든 형식에 스티치 카드를 추가하거나, run-through 뮤직비디오(G9/G10)에서 확인.

### T-03 — 크루 문구와 실제 적용 수치 불일치 (R1/R3, 심각도 높음, 재현율: 가끔(2회))
**재현 절차**: "[TEST] 광고 20초…" (R1). 20초/클립 10초를 요청.
**기대**: 시리즈 = 20s/클립 2개.
**실제**: 크루 응답 문구는 "20초, 10초 클립 2개"라고 말하지만 저장된 시리즈는 **30s/클립 3개**였음(칩 표기 30s). 편 작성 단계에서도 "2개의 10초 클립"이라고 말하면서 3클립(30s)을 써서 앱이 "클립 합계 30초인데 한 편은 20초"로 승인을 차단(방어 동작은 정상). 채팅 수정으로 20s/2clip 정합시킴.
**증거**: 칩 `30s 10s 클립` + 로그 "20 초 광고… 10 초 클립 2 개"; 승인 차단 힌트 `아직 안 됨: 클립 합계가 30초인데 한 편은 20초입니다`.
**의심 위치**: LLM 산수(시리즈/클립 계산을 크루가 직접 함). 추측.
**제안**: 수치 검증(클립 합계=편 길이)은 앱이 이미 차단하므로 좋음. 크루 프롬프트에 "말한 숫자와 시리즈 숫자가 반드시 일치" 강조 또는 생성 후 앱이 확정.

### T-04 — non-music 프로젝트에서 `뮤직 감독` 메시지 반복 표시 (R2/R6, 심각도 보통, 재현율: 가끔)
**재현 절차**: 광고 프로젝트에서 자유 지시를 여러 번 → 로그에 `음악 감독: 먼저 스타일과 가사가 필요합니다…`가 끼어들어 표시됨.
**기대**: 광고에는 음악 관련 응답이 없어야 함.
**실제**: LLM이 `crew:'music'`을 가끔 반환해 해당 메시지가 채팅에 섞임(데이터에는 영향 없음, 노이즈).
**의심 위치**: `ai.ts` 시스템 프롬프트가 이미 형식별 지침을 줄 뿐, 크루 필드 검증이 느슨. 추측.

### T-05 — 안내 문구 vs 실제 버튼 라벨 불일치 (E5, 심각도 낮음, 재현율: 항상)

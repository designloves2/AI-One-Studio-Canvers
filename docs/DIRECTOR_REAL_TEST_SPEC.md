# Director Mode — 실 테스트 명세서 (코드 수정 금지, 문제는 전부 보고)

대상: 이 저장소(`AI-One-Studio-Canvers`)의 Director Mode. 테스트 수행자: 다른 에이전트(DeepSeek 4.1 Flash). 먼저 `CLAUDE.md` §8, `docs/DIRECTOR_VERIFY_CHECKLIST.md`를 읽을 것(검증 대기 항목이 이 명세의 출발점).
이 문서는 **테스트만** 시킨다. 소스·설정·노드 저장소를 고치지 말고, 이상한 점은 §9 양식으로 전부 적어 `docs/DIRECTOR_REAL_TEST_REPORT.md` 로 저장한다(그 파일 외에는 아무것도 커밋하지 말 것).

## 0. 절대 규칙 (어기면 테스트 중단)
1. **코드·문서·설정 수정 금지.** `src/`, `scripts/`, `serve.mjs`, 노드 저장소(`ComfyUI-TJ_NODE*`), `nodes.py`, 서버 설정 파일 모두 읽기만. 고치고 싶으면 보고서에 적는다.
2. **포트 8766 만 사용**: `node node_modules/vite/bin/vite.js --port 8766 --strictPort` (운영 서버 8765 는 사용자가 쓴다, 건드리지 말 것). 끝나면 8766 프로세스를 종료.
3. **GPU 는 16GB 공유.** 실제 생성(이미지·영상·음악)은 §5 이후이고, 시작 전 `nvidia-smi` 와 `GET http://127.0.0.1:8188/queue`(running·pending 둘 다 0)를 확인. 비어 있지 않으면 §5 이후는 하지 말고 "큐가 비어 있지 않아 건너뜀"으로 보고.
4. **로컬 LLM(GGUF / comfy TextGenerate / ollama / custom) 사용 금지** — 생성 중 ComfyUI 가 죽는다. 앱의 LLM 은 **OpenRouter** 로만(§3). 로컬 LLM 호출이 5분을 넘으면 터진 것으로 보고하고 `POST /interrupt` 까지만(재시작 금지).
5. **ComfyUI(8188) 재시작·프로세스 종료 금지**(렌더 중에는 특히). 8188 이 응답하지 않으면 시험을 멈추고 보고.
6. 시험 중 **소스 파일이 바뀌면**(hot reload) 데모 플래그가 풀릴 수 있으니 파일을 저장하지 말 것.
7. 사용자 파일 삭제 금지(`C:\\AI\\output`, `canvases/`, `director/` 안의 기존 파일). 시험이 만든 프로젝트·캔버스·임시 파일은 §8 에서 이름으로 찾아 **목록만 보고**하고, 삭제는 사용자에게 맡긴다.
8. API 키·토큰을 보고서·로그에 쓰지 말 것.
9. 앱의 `confirm/alert` 는 앱 자체 대화상자다. "확인/예" 는 시험 항목이 요구할 때만 누르고, 생성 확인창의 **"예"는 §5 이후 항목에서만** 누른다.

## 1. 환경 준비
- 사전 확인: ComfyUI `http://127.0.0.1:8188` 응답(`GET /system_stats`), TJ_NODE_STUDIO_ONE 라우트(`GET /tj_shared/translate_config`, `GET /tj_node/reflib/assets`) 응답.
- 앱 실행: 8766 으로 vite 개발 서버 → 브라우저로 `http://127.0.0.1:8766/`. 왼쪽 메뉴의 "디렉터 프로젝트"/상단 모드 버튼으로 **Director** 모드.
- 브라우저 도구(Playwright/Chrome 등)로 화면을 조작하고, 가능하면 콘솔 오류(`console.error`)와 네트워크 4xx/5xx 를 수집해 항목마다 첨부.
- 시험 데이터 이름 규칙: 프로젝트 첫 문장 앞에 `[TEST]` 를 붙여 나중에 찾기 쉽게.

## 3. LLM 설정 (실 테스트용)
1. 설정 → Director 전용 LLM(채팅창 왼쪽 아래 ⚙ 버튼으로도 열림)에서 백엔드 **OpenRouter**, 모델은 목록에서 DeepSeek V4 Flash 계열(`deepseek/deepseek-v4.1-flash` 또는 `deepseek/deepseek-v4-flash`; 둘 다 없으면 보고하고 사용자에게 모델 id 를 물어볼 것). 키는 서버에 이미 저장돼 있어야 한다(없으면 "키 없음"으로 보고, 직접 입력하지 말 것).
2. **A3-1** 모델을 비워 두고 요청 → 요청이 나가지 않고 "OpenRouter 모델이 선택되지 않았습니다…" 팝업이 떠야 한다(기본 모델 없음 규칙).
3. Test 버튼 → 응답 OK 와 지연(ms) 기록.

## 7. 경계·오류 시험 (GPU 불필요)
- E1 ComfyUI 응답 없음(포트 틀리게): 오류가 앱을 멈추지 않고 안내가 뜨는지(운영 서버를 건드리지 말고 `COMFY_URL` 을 일부러 틀린 값으로 8766 에서만).
- E2 미래 스키마 프로젝트(읽기 전용 표시) — `director/` 폴더의 파일을 **복사본 이름으로** 읽기만(수정 금지)하는 경우에만, 불가하면 "건너뜀".
- E3 같은 이름 프로젝트/위험한 이름(`..`, `\\`, `:`)으로 시작 → 파일 저장이 안전하게 거절/정리되는지.
- E4 좁은 창(폭 <900px, 모바일 375px): 채팅이 아래로 쌓이고 단계 줄·회차 줄이 가로 스크롤, 가로 스크롤바 없는 본문, 승인 버튼 접근 가능.
- E5 한국어/영어 문구: 영어 키가 그대로 보이는 한글 누락 라벨, 단어 중간 줄바꿈, 겹치거나 잘리는 글자(스크린샷 첨부).
- E6 동시 조작: 작업팀이 일하는 중 입력·승인·단계 이동 시 중복 실행이나 상태 꼬임이 없는지.
- E7 큰 프로젝트: 30편 설정에서 회차 줄(가로 스크롤)·일괄 승인 응답성.
- E8 콘솔: 모든 시험 중 `console.error`, React 경고, 네트워크 4xx/5xx 를 항목 번호와 함께 모은다.

## 8. 정리
- 8766 서버 종료, 브라우저 탭 닫기. 시험이 만든 `[TEST]` 프로젝트(`director/`), 캔버스 파일(`canvases/`의 `[TEST]`·`- ep01`·`- casting`·`- song`), ComfyUI input/output 의 임시 파일, 에셋 라이브러리의 시험 에셋 **목록**을 보고서 맨 끝에 적는다(삭제는 사용자에게).
